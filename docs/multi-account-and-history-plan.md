# 多账号与历史记录功能规划

日期：2026-11-13。状态：按后续实施指令落地，并追加个人书架；部署操作见 [账号、书架、历史与阅读进度](accounts-and-history.md)。

本文保留设计基线、数据约束和验收要求；文中“当前代码”描述规划时的状态，实施后的模块与差异见第 13 节。

## 1. 已确认的方向与第一版范围

**已确认：所有账号共享同一文档库，各账号独立保存搜索历史、阅读历史、阅读进度和个人偏好。** 登录后的普通用户与管理员拥有相同的文档检索、阅读范围；管理员额外拥有账号管理权限。

建议保留现有 Bottle、模板页面、Recoll 检索和阅读器，新增一个本机 SQLite 数据库管理应用数据。Recoll 继续负责全文索引；SQLite 不保存文档正文，也不替代 Recoll。

“历史记录”在本规划中包含搜索历史、最近阅读、跨设备继续阅读。这是建议的功能范围；下表中除共享文档库以外的默认值均为设计建议，可在实施前调整。

| 项目 | 第一版建议 |
| --- | --- |
| 使用场景 | 单台服务器上的个人、家庭或小团队共享检索服务 |
| 账号来源 | 管理员创建；关闭公开注册 |
| 角色 | 管理员、普通用户 |
| 登录方式 | 用户名和密码；服务端会话 |
| 匿名访问 | 账号功能启用后，搜索、正文、导出和个人数据均要求登录 |
| 账号切换 | 同一浏览器配置文件同一时刻登录一个账号；支持退出后切换。不同浏览器或设备可同时登录不同账号 |
| 搜索历史 | 成功的主动搜索按事件保存，可重做、删除、清空和暂停记录 |
| 阅读历史 | 每个账号、每篇文档聚合一项最近阅读记录 |
| 阅读进度 | 按账号同步，以结构化位置恢复；不将滚动操作保存为历史事件 |
| 个人书架 | 搜索结果和阅读器可加入/移出，账号独立，显示进度并继续阅读 |
| 偏好 | 搜索显示与阅读字体等适合跨设备的设置归账号；设备挂载映射保留为设备设置 |
| 运维方式 | 一个数据库文件、少量新增依赖、显式迁移和备份流程 |

第一版不包含：账号间文档授权差异、组织/团队体系、第三方登录、邮件找回密码、公开注册、批注、逐次访问审计报表、历史全文搜索引擎、多服务器共享写数据库。需要不同文档权限时，另行设计索引和目录授权，不能把本方案的个人数据隔离当作文档 ACL。

## 2. 当前代码提供的基础与需要调整的位置

以下以文件和函数名定位，避免其他界面改动使行号失效。

| 现状 | 代码依据 | 对规划的影响 |
| --- | --- | --- |
| Bottle 路由直接提供搜索、预览、下载和阅读器 | `webui.py` 的 routes 区域 | 需要统一认证入口，不能只保护首页 |
| 设置来自 Recoll 配置、全局 `DEFAULTS` 和 Cookie | `get_config()`、`set_settings()` | 分离只读服务配置与账号偏好；移除 GET 修改设置的行为 |
| 配置读取会修改 `os.environ` 和 `DEFAULTS` | `get_config()` | 用户上下文必须保存在请求内，不能通过修改全局状态切换账号 |
| 搜索函数被结果页、导出、文档定位复用 | `recoll_initsearch()`、`recoll_search()`、`resolve_doc_from_result_query()` | 历史写入放在主动搜索流程中，不能放进底层搜索函数 |
| 查询执行异常被捕获后继续返回 | `recoll_initsearch()` | 先区分“查询失败”和“成功但零结果”，再记录历史 |
| 文档通常通过重新查询后的结果序号定位，可选 `rcludi` | `resolve_doc_from_result_query()`、`views/result.tpl` | 历史需要独立文档标识，不保存结果序号作为长期身份 |
| PDF URL 可能附加搜索词/页码，再生成结果 `sha` | `recoll_search()` | 当前结果 `sha` 也不能直接用作文档主键 |
| 阅读进度按文件路径保存在 localStorage | `static/reader/app.js` 的 `savePosition()`、`loadPosition()` | 需要服务端保存及浏览器内的账号隔离 |
| 字体等使用全局 localStorage 键 | `FONT_SIZE_STORAGE_KEY`、`persistFontSize()` | 切换账号后不能继续使用上一账号偏好 |
| 目录游标只有全局写入，没有完整恢复流程 | `saveFolderCursor()`、`loadFolderMode()`、`openIndex()` | 改为按目录保存最后一本书，不依赖列表下标；现有写入还使用初始目录元数据中的下标 |
| 阅读令牌包含可解码路径与有效期，无账号绑定 | `make_reader_token()`、`read_reader_token()` | 令牌不能代替登录；需要绑定当前会话并在请求时复验 |
| 临时文档路由直接以整个临时目录为根目录 | `server_staticdoc()` | 改为经过授权的具体资源映射，数据库及密钥绝不能放入该目录 |
| EPUB/CHM iframe 已禁止脚本，但原始正文可直接打开 | `reader_epub_content()`、`reader_chm_content()`、`reader_file()`、`preview()` | 账号上线前需补齐服务端正文隔离，不能只依赖父页面 iframe |
| 独立服务默认 8 个 Waitress 工作线程，也支持 WSGI | `webui-standalone.py`、`webui-wsgi.py`、`README.rst` | SQLite 连接、迁移和会话必须兼容多线程及同机多进程 |

## 3. 用户流程与页面

### 3.1 首次启用和账号生命周期

1. 部署者配置应用数据目录，通过服务器本地管理入口初始化数据库和首个管理员；不提供“首个网页访问者成为管理员”的流程。
2. 初始化完成前，应用显示服务未准备好，不开放原有匿名搜索入口。生产环境关闭当前独立入口中的 Bottle debug。
3. 管理员创建普通账号并设置一次性初始密码。用户首次登录必须改密，改密前只允许访问改密与退出接口。
4. 用户可以改自己的密码、查看当前登录设备、撤销单个设备或退出所有设备。密码重置由管理员执行，不引入邮件依赖。
5. 管理员可以创建、停用、启用、重置密码、调整角色和删除账号。停用保留个人数据；删除清除该账号的会话、偏好、历史和进度。
6. 停用、密码重置和角色变化立即撤销相关会话。删除、停用或降级最后一个可用管理员必须在事务内阻止；提供本地管理员恢复入口。

管理员界面不提供查看其他用户搜索词、阅读记录或进度的功能。数据库文件的服务器维护者仍具有底层数据访问能力，这种产品权限隔离不等于对服务器维护者加密。

### 3.2 页面布局

| 页面或入口 | 内容 |
| --- | --- |
| 登录页 | 用户名、密码、错误提示；成功后返回本站原目标页面 |
| 全局账号入口 | 当前账号、历史记录、个人设置、退出；管理员额外显示账号管理 |
| 历史页：搜索 | 时间、检索表达式、目录/日期筛选、结果数；重新搜索、单条删除、清空 |
| 历史页：阅读 | 标题、格式、最近阅读时间、可用进度；继续阅读、移除最近阅读、清除该书进度 |
| 搜索首页 | 最近阅读的少量入口，例如最近 5 本；完整列表进入历史页 |
| 我的书架 | 当前账号主动加入的文档、格式、进度、继续阅读与移出入口；不随历史清理移除 |
| 个人设置 | 搜索显示设置、阅读偏好、三个独立记录开关、改密、设备会话 |
| 账号管理 | 账号列表、角色、状态、创建/重置/停用/删除；不显示个人历史 |
| 阅读器 | 显示同步状态和账号身份；保存失败、登录过期、进度冲突有可见反馈 |

仍使用现有服务端模板和少量前端脚本，不为这些功能引入新的前端框架。界面日期按浏览器时区展示，数据库统一记录 UTC 时间。

## 4. 身份认证与访问边界

### 4.1 密码和会话

- 用户名建议限制为 3–32 位 ASCII 字母、数字及 `._-`，以小写规范值唯一；显示名称另存并允许中文。第一版不支持修改登录名。
- 密码使用成熟库提供的 Argon2id 哈希，保存含算法、盐和参数的编码结果，不保存明文或可逆密文。建议采用不低于 19 MiB、2 次迭代、并行度 1 的起点，在目标设备上测量耗时与并发内存后调整；依赖安装失败应报错，不静默切换为快速哈希。[依据：OWASP 密码存储](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)
- 产品建议密码长度 15–128 个字符，允许粘贴和密码管理器，不强迫特定字符组合、不定期强制改密；初始密码和管理员重置密码要求首次使用后更换。
- Cookie 只携带密码学随机的不透明会话令牌，数据库保存令牌哈希。不要将身份令牌放进 localStorage，也不需要引入 JWT。
- Cookie 使用 `HttpOnly`、`SameSite=Lax`，HTTPS 部署使用 `Secure`，不设置宽泛 Domain；Path 与应用挂载前缀一致。登录成功轮换会话和 CSRF 上下文；退出在服务端撤销会话，而不只是删除 Cookie。[依据：OWASP 会话管理](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)
- 建议默认空闲 7 天、绝对 30 天过期；每次请求检查过期和账号状态，最近活动时间最多每 5 分钟更新一次，避免每个正文分片都写库。浏览器关闭后是否保留由明确的“保持登录”选项控制，服务器绝对期限始终生效。
- 登录失败使用统一提示，并按账号规范值和来源地址实施有限退避/限速；限速计数支持多进程共享并及时过期，不用永久锁号。来源地址只信任明确配置的反向代理。
- 登录、退出、改密、账号管理、偏好修改及历史写接口验证 CSRF；登录页可使用独立短时匿名 CSRF 上下文。`next` 只允许应用前缀下的本站相对路径，阻止开放重定向。

### 4.2 路由保护矩阵

所有新路由默认需要登录，仅明确的公开清单例外。服务端从当前会话取得用户 ID，客户端传入的 `user_id` 不能决定数据归属。

| 路由范围 | 访问规则 |
| --- | --- |
| 登录页、必要的 `/static/*`、不含私人信息的 `/osd.xml` | 可匿名访问；static 根目录只放应用资源 |
| `/`、`/results`、`/reader`、历史页、个人设置页 | 登录后访问 |
| `/api/reader/*` 的 book、folder、file、manifest、chunk、content | 每次校验登录及文档范围；不能仅验证 URL 令牌 |
| `/preview/*`、`/download/*`、临时文档资源 | 登录后访问，走统一文档解析与授权 |
| `/json`、`/csv` | 登录后访问，并在服务端执行 `webui_nojsoncsv` 限制 |
| 个人历史、进度、偏好 API | 当前账号范围内读写；猜中他人记录 ID 仍不可访问 |
| 账号管理 API | 管理员权限；角色和可用状态每次按服务端数据判断 |
| 原 `/set` | 停止通过 GET 写入；新写操作采用 POST 和 CSRF |

HTML 页面未登录时跳转登录；API 和正文获取请求返回明确的 401，避免阅读器收到状态为 200 的登录 HTML。禁止访问其他账号的私人记录统一表现为不存在；已登录但角色不足返回 403。

`webui_nosettings` 明确解释为禁止用户修改搜索展示设置，由服务端落实；改密、会话撤销和个人数据删除仍可使用。`webui_maxperpage` 等管理员硬限制必须在实际执行时生效。

### 4.3 阅读正文、临时文件和缓存

这些是新增账号功能的必要接入条件：应用会把来源于文档的内容和账号页面放在同一服务上。

1. 阅读令牌改为引用服务端文档/资源身份，绑定用户和当前会话，限定用途与有效期。每次正文请求仍检查会话是否有效。多进程共用持久、受权限保护的签名密钥；退出、改密、停用后旧令牌不可继续使用。
2. 保留 EPUB/CHM 现有的无脚本 iframe 限制，并为直接访问的 HTML、SVG、预览等正文响应增加服务端 CSP sandbox 和资源加载约束。需要父页面读取滚动位置时可评估保留 `allow-same-origin`，但不得同时放开文档脚本；表单、顶层导航及外部资源也要受到限制。原始下载通过 attachment 提供，不能借直接打开正文 URL 绕过隔离。[依据：MDN CSP sandbox](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/sandbox)
3. 不将脚本禁用寄托于 Cookie 的 HttpOnly 属性。还要检查阅读器解析生成的 DOM、响应 MIME、`nosniff`，以及不经过 iframe 的访问路径。安全策略必须与 CHM 链接、EPUB 图片和 PDF 阅读进行兼容验证。
4. `/staticdoc/*` 改为只能读取经服务端登记的特定提取资源；临时路径不是授权依据。PDF 搜索跳转也接入该资源流程。数据库、备份、日志和密钥放在独立持久目录。
5. 账号页、历史、进度、结果页和带个人数据的 API 使用 `Cache-Control: no-store`。第一版正文也优先采用私有、不持久缓存策略，验证 Range/分片读取；避免现有一小时缓存绕过退出后的访问校验。
6. 退出或换号时，阅读器销毁已加载正文、撤销对象 URL、清除内存状态并停止上传。通过标签页间通知和页面重新激活时的会话检查覆盖后台标签页；已经下载到外部的文件无法撤回。
7. 结果中的外部 mount URL、`file://` 的访问控制属于外部文件服务或操作系统。账号系统只保护经过本应用的请求；不能承诺外部 Open 链接受本应用撤销会话控制。

## 5. 历史记录的具体语义

### 5.1 搜索历史：记录一次搜索，而非每个请求

建议以独立搜索事件区分主动操作与页面读取，避免仅根据 `page=1` 或短时间去重猜测用户行为。

1. 搜索表单和“重新搜索”提交到受 CSRF 保护的搜索入口。服务端校验参数；开启搜索记录时，为当前账号创建待完成的 `search_id`，保存搜索条件与设置快照，再跳转到现有结果页。关闭记录时只校验并跳转，不创建事件或保存查询快照。仅事件写入失败时也可转入无事件查询，同时明确提示本次历史未保存；认证失败不能走此降级路径。
2. `/results` 首次执行使用事件保存的条件和偏好快照，并重新套用当前管理员硬约束；实际执行值写回事件，避免 POST 到 GET 之间其他标签页改设置造成记录与结果不符。成功完成后将事件原子地标记为成功，保存完成时间及结果数；同一事件只能完成一次。零结果是成功，执行错误是失败，不显示为成功历史。
3. 分页、刷新、浏览器返回及查看全部结果沿用已有事件；预览、阅读器、下载和 JSON/CSV 导出不创建新事件。用户再次点击搜索，即使条件相同，也创建新事件。
4. 不在 `recoll_initsearch()` 或 `recoll_search()` 内写历史。待完成和失败事件短时清理，页面历史列表只展示成功事件。
5. `search_id` 是幂等关联标识，不是访问凭据。读取/完成事件时核对当前账号、搜索条件和记录开关；复制他人的结果链接只按 URL 条件执行共享库搜索，不读取或更新对方事件。
6. 保留旧式 GET `/results?...` 和 OpenSearch 链接可用。**第一版建议这些没有主动搜索事件的兼容入口仅显示结果，不新增历史**；用户在页面再次提交后正常记录。如希望浏览器搜索插件也自动记录，后续增加显式事件接入，不把所有 GET 当作主动搜索。
7. 删除历史、关闭记录或账号切换后，旧页面请求不能恢复已删除的事件。未知/过期 `search_id` 可继续显示按 URL 查询的结果，但不据此补建历史。

保存的条件包括：原始 `query`、`dir`、`before`、`after`、`sort`、`ascending`、实际生效的 `stem`/`collapsedups`，以及当前索引集合的稳定标识和查询规则版本。保留检索表达式原文，不任意改大小写、引号内空格或 Recoll 语法。

`page`、`resnum`、`mode`、临时 token 不参与搜索语义指纹；`highlight`、`snippets` 可作为展示快照。重新搜索从第一页开始，并重新应用当前管理员约束，结果和历史结果数可能因索引变化而不同。服务端规则版本变化时告知用户，不复活旧的权限或配置。

第一版按时间显示事件，不做搜索次数统计。可使用语义指纹辅助将来聚合重复搜索，但指纹不替代事件幂等键。纯空白主页不记录；包含有效目录/日期筛选的空查询可以记录。

### 5.2 阅读历史：只有实际打开正文才算阅读

- 前端在文档正文成功可读后提交一次打开事件；仅访问 `/reader` 壳页、获取 manifest、扫描目录或预取下一章不算已读。打开句柄绑定打开时的账号、会话及阅读/进度代际，回执不能在到达时换取新代际来绕过删除。
- 服务端核对会话绑定的文档句柄和账号记录设置，更新该账号、该文档的最近阅读记录。前端回执只是界面活动依据，不宣称能证明人实际阅读了内容。
- 同一成功打开回执分别按开关处理：开启最近阅读才更新 `reading_history`；开启进度同步才建立缺失的 `reading_progress`，目录模式同时更新 `folder_resume`。已有位置不得在初始化时覆盖；关闭最近阅读不影响独立启用的进度同步。恢复已有位置的读取可以先于回执，创建新记录则必须通过有效回执。
- 同一本书重复打开只更新最近时间，列表不新增重复项。进度同步不增加打开次数；第一版无需提供次数统计。
- 第一版不把预览、下载和外部 Open 点击列为阅读历史。以后增加“访问记录”时可独立标明动作，不能用下载代替阅读。
- 历史项显示最后已知的标题、格式和最近时间。文档删除、移出允许目录或无法定位时显示“文档不可用”，保留可删除记录，不尝试打开相同结果序号的另一篇文档。

### 5.3 稳定文档身份与目录阅读

引入由服务端分配的不透明 `document_id`，独立于搜索结果位置、下载 URL 和阅读令牌。

| 内容 | 规则 |
| --- | --- |
| 定位信息 | 当前共享库的稳定命名空间 + 原始规范化 URL/真实文件路径 + 容器内部 `ipath` |
| Recoll 定位提示 | 保存可用的 `rcludi`；重建索引后需校验是否仍指向同一来源 |
| 本地普通文件 | 搜索结果和目录扫描以同一规范路径、空 `ipath` 合并引用 |
| 容器内文档 | 保留父来源与 `ipath`，不能把提取临时路径当作文档身份 |
| 内容版本 | 单独记录 `mtime_ns + size` 等廉价变更标记及解析器版本；不与 document_id 混为一体，也不声称它等价于内容哈希 |
| 从历史重开 | 按 document_id 解析 → 校验现有来源及允许根目录 → 生成新的阅读/下载资源句柄 |

定位必须使用未经 PDF 搜索锚点加工的原始 URL；本地文件执行 realpath 和目录边界校验，保留容器语义。不能凭前端上传的任意路径建立授权；目录扫描的未索引文件也只能来自服务端验证过的根目录。

第一版不承诺自动跟踪文件重命名或跨目录移动。内容已改变时，先校验结构化位置是否仍可用；无效则提示从头或可用章节开始，不强行恢复到错误位置。容器内文档若当前阅读器不能安全提取，显示不支持继续阅读，可保留已有预览/下载能力。

目录继续阅读按“账号 + 稳定目录标识”保存 `last_document_id`，重进后重新扫描并匹配该文件，不保存旧 `currentIndex` 作为身份。目录递归扫描仍遵守现有限额；超过 1000 本或目标不在截断列表时应明确提示，并允许按已验证的文档标识单独打开。目标消失时不静默换到别的书。

### 5.4 跨设备进度与冲突

| 格式 | 首期位置表示 |
| --- | --- |
| TXT | 分块版本、块索引、块内比例；像素位置仅作辅助 |
| EPUB | 章节 href/索引、章节内比例，必要时保留引擎定位数据 |
| CHM | 已验证的内部 href、滚动位置；跨屏幕布局允许近似恢复 |
| PDF | 引擎版本、页码、可用的页内位置 |
| 其他阅读器格式 | 版本化的引擎 position；不支持可靠位置时仅保存最近阅读 |

位置 JSON 设置格式白名单、版本和大小上限，例如 16 KiB；不反序列化可执行对象。百分比仅作展示，不能替代定位信息；现有 TXT/EPUB 百分比也不能用来自动判断已读完。

同步流程：

1. 打开文档时先加载服务端位置并完成恢复，恢复前不允许初始化的 0% 覆盖旧数据。
2. 浏览器内存立即更新位置，待同步状态绑定应用、账号、会话和文档；首版不在 localStorage 持久保存正文定位数据。服务端只在位置变化时每 5–10 秒合并写入，换书、页面隐藏时补交；不保证浏览器关闭瞬间一定送达，重载以后以服务端成功提交的位置为准。
3. 每次更新带期望 `revision`、标签页写入标识及单调序号。服务端通过条件更新拒绝旧修订和乱序请求；响应冲突时不自动用旧位置覆盖新位置。
4. 两个设备同时阅读时提示已有更新，并提供“采用已保存位置”或“从当前设备继续”。后者重新取得修订号后明确接管；不以最大百分比合并，因为用户可能正在回读。
5. 写入身份来自会话，同时校验页面的 CSRF/会话上下文；退出和切号后取消请求、计时器与重试，旧账号数据不能在新账号会话下上传。
6. 删除、清空或关闭同步时，递增相应的记录代际；旧页面携带的代际失效，不能由延迟请求重新创建数据。进度上传只更新已建立的当前记录，不能无条件 upsert 复活已删除记录。第一版采用账号级的分类代际，单条删除也可能使该类其他已打开页面的写入上下文失效；界面提示重新打开以恢复同步，不静默替旧请求刷新代际。重新开启记录必须从一次新的显式打开开始。
7. 离线或暂时写入失败时，已加载正文可继续阅读并显示“尚未同步”。待同步数据只允许当前账号、有效代际重试；重新登录后先比对服务端修订，不静默覆盖其他设备的更新。

### 5.5 保留、暂停与删除

| 数据 | 建议默认保留 | 用户控制 |
| --- | --- | --- |
| 搜索历史 | 90 天且最多 500 次成功事件，先到限制者清理 | 独立开关、单条删除、清空搜索历史 |
| 最近阅读 | 180 天且最多 1000 篇文档 | 独立开关、移除最近阅读、清空最近阅读 |
| 阅读进度和目录续读 | 最后更新后 365 天且每类最多 1000 项 | 独立同步开关、清除该书进度、清空全部阅读数据 |
| 书架 | 主动移除或删除账号前保留；书架文档的进度不受自动期限/数量淘汰影响 | 加入、移出；清空历史保留书架，显式清除进度仍生效 |
| 会话、待完成搜索、限速桶 | 到期后清理；过期即时禁止使用 | 撤销会话；其余由服务维护 |

三项记录开关分别控制搜索历史、最近阅读、进度同步，默认开启；首次使用和设置页说明它们的用途。停止记录保留已有数据，删除需要明确的独立操作。

“移除最近阅读”保留继续阅读位置，按钮旁说明这一点；“清空全部阅读数据”同时删除阅读历史、进度、目录续读和对应浏览器缓存。全部个人历史清理还应包含搜索事件。前端和服务端都执行代际检查，避免后台标签页把记录写回来。清理保留期的数据在读取时也应过滤，不能依赖定时任务准时运行。

应用日志不记录密码、会话令牌、正文或完整搜索词；原 `logquery` 默认关闭并由部署者控制。反向代理访问日志、浏览器自身历史可能仍包含搜索 URL，应用内“清空历史”不声称能删除这些外部副本。数据库备份也按单独的保留策略轮换，不承诺一次应用删除会抹除已有备份。

## 6. SQLite 逻辑数据模型

以下是逻辑表和字段约束，不是最终 DDL。第一版采用直接的数据访问层与 Python 标准库 `sqlite3`，暂不引入 ORM 或额外数据库服务。可变结构用带版本的 JSON 文本；需要唯一性、权限筛选、排序的字段独立存列。

| 表 | 主要字段 | 关键约束/索引 |
| --- | --- | --- |
| `schema_migrations` | version、applied_at | version 唯一；迁移版本可审计 |
| `users` | id、username_normalized、display_name、password_hash、role、status、must_change_password、auth_version、created_at、updated_at | 用户名唯一；角色/状态限定；ID 不随显示名改变 |
| `sessions` | id、token_hash、user_id、auth_version、created_at、last_seen_at、idle_expires_at、absolute_expires_at、revoked_at、device_label | token_hash 唯一；按 user_id 和到期时间索引；原始令牌不入库 |
| `user_settings` | user_id、preferences_json、schema_version、search_history_enabled、reading_history_enabled、progress_sync_enabled、各类 history_epoch、updated_at | user_id 一对一；JSON 仅含白名单设置 |
| `document_refs` | id、library_key、locator_key、source_url、source_path、ipath、rcludi、title、format、content_version、last_verified_at | library_key + locator_key 唯一；定位摘要冲突时核对完整元组 |
| `search_history` | id/search_id、user_id、query_json、query_fingerprint、settings_snapshot、scope_version、status、history_epoch、created_at、completed_at、result_count | 事件 ID 唯一；按 user_id + completed_at + id 排序；完成状态原子转换 |
| `reading_history` | id、user_id、document_id、title_snapshot、first_opened_at、last_opened_at | user_id + document_id 唯一；按 user_id + last_opened_at + id 排序 |
| `reading_progress` | user_id、document_id、position_json、position_version、content_version、revision、writer_id、writer_seq、progress、origin、imported_at、updated_at | user_id + document_id 唯一；修订号条件更新；导入来源单独标记 |
| `folder_resume` | user_id、folder_key、last_document_id、revision、updated_at | user_id + folder_key 唯一；目录来源由服务端验证 |
| `bookshelf` | user_id、document_id、added_at、updated_at | user_id + document_id 唯一，删除账号级联删除，按加入时间稳定分页 |
| `login_throttle` | bucket_key、window_start、failure_count、blocked_until、expires_at | bucket_key 唯一；按过期时间清理；不保存提交的密码 |

补充约束：

- 每个连接启用外键；个人表引用 users，删除账号级联删除其私人数据；停用不删除。文档引用不包含用户行为，删除账号不删除共享文档或 Recoll 索引。
- 历史、进度、目录续读分别建模，使“清除列表”和“清除继续阅读”拥有明确语义。各类代际在账号设置中维护；删除时同事务更新，客户端只携带不能自行提升。
- 文档引用仅在实际使用时建立，不把整个 Recoll 索引导入 SQLite；没有任何个人记录引用的定位行可定期回收。历史接口不能因此成为枚举服务器路径的公共接口。
- 不落库临时正文、短期下载链接、提取缓存路径或完整搜索结果列表。源路径只在服务端定位所需范围保存；对外优先返回不透明 ID 和适当的显示标签。
- 所有数据访问方法显式接收当前用户上下文，查询、修改、删除必须同时限制 `user_id`；不能先按记录 ID 查询后依赖页面隐藏来隔离。
- 列表使用时间 + ID 的稳定游标分页，建议每页 20 条、上限 100 条；所有 SQL 值使用绑定参数，排序字段走白名单。

## 7. 数据库运行、配置与恢复

### 7.1 连接与事务

- 数据库使用绝对路径放在本机持久目录，例如服务部署时的 `/var/lib/recoll-webui/app.sqlite3`，由服务账号访问；不依赖进程当前目录，不放在源码、static、Recoll 临时目录或网络挂载盘。
- 使用请求级连接，流式正文开始前即释放数据库资源；不跨线程共享全局 connection。每连接设置外键和合理 busy timeout，建议初值 3 秒；初始化时选择 WAL，短事务执行写入。
- WAL 允许读写并行，但同时仍只有一个写者；同机多进程可共用数据库，不把数据库文件放到 NFS/SMB 实现跨机器共享。[依据：SQLite WAL](https://www.sqlite.org/wal.html)
- 实施时核验 Python 实际链接的 SQLite 版本。SQLite 官方记录了多连接 WAL 写入/checkpoint 竞争下的 WAL-reset 问题，修复版本包括 3.51.3 及相应维护分支补丁 3.44.6、3.50.7；上线使用包含该修复的受支持版本，并核对发行版是否回补。[依据：SQLite WAL-reset 说明](https://www.sqlite.org/wal.html)
- 事务内不执行 Recoll 查询、密码哈希、文件读取/解压或网络操作。认证查询快速结束，进度节流后再写；长正文请求不持有事务。
- 锁竞争采用有上限且有总时限的重试，只重试可安全重放的操作；监测锁等待、失败率、WAL 大小和写入延迟。账号/会话查询不可用时拒绝访问，不能回退为匿名模式。
- 仅历史或进度写入失败时允许已经通过认证的搜索/阅读继续，页面明确显示未保存；设置、账号管理和删除操作必须以事务提交成功作为成功依据。

### 7.2 配置边界

| 服务级配置，建议名称可在实施时统一 | 责任 |
| --- | --- |
| `RECOLL_WEBUI_DB_PATH` / 应用数据目录 | 数据库和相关持久文件位置 |
| 持久阅读令牌/回执签名密钥 | 多进程一致，独立于数据库和源码保存 |
| Cookie 安全模式、会话期限、可信代理与挂载前缀 | 支持 HTTPS 反向代理、独立服务及 WSGI 子路径部署 |
| 历史期限、数量上限、正文/历史请求限额 | 保护存储和服务容量 |
| 清理与备份调度 | 由 systemd timer/部署工具执行，或采用单执行者维护任务 |
| Recoll 索引、允许目录、queryfrag、同义词文件、导出限制 | 仍由管理员配置，不写入个人偏好 |

个人设置采用“管理员硬约束 > 用户已保存偏好 > 管理员默认值 > 应用默认值”的优先级。每页数量、摘要长度、字体等校验类型和范围；只允许白名单字段，不能覆盖索引路径、服务端密钥或日志策略。

现有 mount 映射可能依赖某台客户端的盘符/挂载点，第一版作为账号隔离的设备设置保留，管理员提供默认值；限制可呈现的 URL 协议。现有 parserRegex 虽保存到 localStorage，但阅读器实际传入空值，首期不把它当作已经可用的同步功能，启用需单独评估。

### 7.3 迁移、备份和故障恢复

1. 迁移在启动工作进程前显式执行，使用跨进程锁并校验版本；普通 WSGI 请求不得自动并发建库。多个进程必须读到相同数据库和密钥配置。
2. 首次启用前完成数据库初始化、管理员创建和目录权限检查，再开放流量。后续迁移先备份，成功后才启动新版本；schema 比程序新时拒绝写入。
3. 使用 SQLite 在线备份 API 生成一致性备份，或完全停止写入后执行冷备；不能在服务运行时只复制主 `.sqlite3` 文件而忽略 WAL 状态。[依据：SQLite Backup API](https://www.sqlite.org/backup.html)
4. 建议每天备份、保留最近 7 份，迁移前额外备份；备份目录与数据库具有同等级访问限制。签名密钥单独备份，并制定恢复或轮换方式。
5. 恢复时停止全部写进程，校验备份完整性及外键、恢复匹配的程序/schema，再撤销恢复出来的所有会话并更新会话/记录代际，防止旧登录和旧待同步请求重新生效。
6. 清理过期事件、会话、限速桶和无人引用文档采用小批事务及单执行者调度；不要每个 worker 同时执行，也不要在请求路径运行 VACUUM。
7. 回滚必须考虑数据库版本。不能简单切回未认证的旧程序并暴露原入口；需要维护页或反向代理继续限制访问，必要时恢复匹配备份并说明回滚期间的数据损失。

## 8. 旧 Cookie / localStorage 数据的处理

历史匿名浏览器数据没有可靠的账号归属，**不能自动归入第一个登录的账号**。

- 首次登录后可提供一次性的“导入本浏览器旧设置与进度”，展示类别和数量，由用户主动选择；不导入为默认。
- 只读取已知旧键和 Cookie 白名单。服务端重新验证路径、来源和位置格式后映射到 document_id，拒绝任意路径、越界 JSON 和无效位置。
- 旧阅读位置没有可信时间及版本，导入时标记“从本浏览器导入”，记录导入时间，不伪造最近阅读时间；不凭导入进度补写阅读历史。
- 已存在服务端进度时默认保留服务端版本，需要明确选择才覆盖。旧目录下标不直接导入，不能保证它仍指向同一本书。
- 导入成功后清除对应旧键，记录此浏览器已处理状态；拒绝导入时提供删除旧本地数据入口。账号模式下停止读取全局旧键，避免切号串数据。
- 新缓存按应用实例、账号和文档分区；退出清理敏感缓存。其他标签页收到退出/清理通知后立即停止保存，重新激活时再次验证会话。

## 9. 计划中的接口和模块边界

下面是接口契约方向，不代表现在创建这些文件或路由；名称可在实施时统一，但身份、幂等和删除语义应保持一致。

| 接口组 | 预期职责 |
| --- | --- |
| 登录、退出、当前会话、改密、设备撤销 | 建立和撤销服务端会话；账号状态检查 |
| 管理员账号接口 | 创建、角色/状态调整、重置、删除；保护最后一个管理员 |
| `POST /search` + 现有 `GET /results` | 发起搜索事件、跳转、执行并完成一次历史记录 |
| 搜索历史列表/删除/清空 | 仅当前用户；重新搜索通过搜索入口创建新事件 |
| 阅读打开回执、阅读历史列表/删除 | 基于当前会话授权的文档，聚合最近阅读 |
| 按 document_id 获取/更新进度 | 结构校验、版本检查、修订冲突与代际检查 |
| 按 document_id 重开、按目录恢复 | 不依赖历史 query/resnum；重新授权并生成资源 URL |
| 个人偏好及旧数据导入 | 字段白名单、设备/账号设置边界、一次性导入 |

建议从 `webui.py` 中抽出数据库访问、认证/会话、个人设置、历史/进度、文档定位五个职责模块。保留现有路由编排和 Recoll 适配，不做全站框架重写；SQLite 访问集中管理，模板和阅读器不直接操作数据库。

预计涉及的现有位置：`webui.py` 的配置/路由/文档定位函数，`webui-standalone.py` 与 `webui-wsgi.py` 的初始化边界，`views/header.tpl`、`views/search.tpl`、`views/settings.tpl`、`views/result.tpl`、`views/reader.tpl`，`static/reader/app.js` 的位置和打开流程，以及部署说明。账号/历史页面、数据访问模块、迁移和管理入口在实施阶段新增。

## 10. 实施顺序与完成条件

各阶段可以拆分交付，但在第 2 阶段访问边界完成前，不向真实多用户开放账号模式。

| 阶段 | 工作 | 完成条件 |
| --- | --- | --- |
| 1. 数据和初始化 | 确定表结构、存储目录、连接管理、迁移、首管理员和本地恢复入口 | 空目录可初始化；启动/迁移失败明确；备份可恢复 |
| 2. 认证和正文边界 | 登录/会话/CSRF、统一鉴权、会话撤销、令牌绑定、临时资源和正文隔离、生产 debug 配置 | 所有旧入口均受保护；旧令牌退出后失效；直接打开正文不获得账号页面权限 |
| 3. 账号和偏好 | 管理员操作、个人设置、会话列表、旧浏览器数据选择性迁移 | 两个账号独立；最后管理员受保护；设置硬限制生效 |
| 4. 搜索历史 | 显式搜索事件、成功/失败区分、列表、重做、删除、保留策略 | 翻页/导出/预览不新增搜索，刷新不重复，清空后旧事件不复活 |
| 5. 阅读历史与继续阅读 | 文档 ID、正文打开回执、各格式位置适配、目录恢复、同步/冲突/删除代际 | 换设备可恢复可支持格式，目录换书正确，旧请求不覆盖或复活数据 |
| 6. 集成与部署 | 双账号、多标签页、多进程、压力与故障验证，更新部署说明 | 下方验收矩阵通过；完成升级、备份、恢复和回滚演练 |

建议优先让账号和搜索历史形成可独立验收的第一批实现，随后加入阅读进度；完整需求以第 6 阶段完成为准。阅读安全和账号隔离不能排在最后补做。

## 11. 验收矩阵

| 场景 | 必须满足的结果 |
| --- | --- |
| 账号 A 与 B 使用同一文档库 | 搜索/正文范围相同，历史、进度、字体和个人设置互不影响 |
| A 猜测 B 的历史、进度、会话 ID | 无法读取、修改、删除；客户端 user_id 参数无效 |
| 匿名访问任意搜索、导出、预览、下载、reader 子路由和临时资源 | 无正文/结果泄露；HTML/API 的认证失败行为符合约定 |
| 退出、停用、改密后复用旧 Cookie/reader token | 服务端拒绝；多 WSGI worker 结果一致 |
| CSRF、恶意 next、未授权管理员操作 | 均被拒绝，错误不暴露账号是否存在或内部路径 |
| 直接打开 HTML/EPUB/CHM/SVG 正文与预览 | 文档脚本/表单不能借应用同源访问账号功能；正常目录、样式和翻页仍可用 |
| 重复刷新、翻页、JSON/CSV 导出、下载/预览、浏览器返回 | 不增加搜索事件；主动重新搜索新增一次 |
| 成功零结果、Recoll 执行失败、无事件的旧 GET 链接 | 分别表现为成功历史、失败不入历史、兼容读取不新增历史 |
| 目录预加载、manifest/分片重试、打开失败 | 不产生虚假的最近阅读 |
| 重建索引、改变排序、文件消失/移动、容器内文档 | 不依赖 resnum；找不到时明确不可用，不打开另一文档 |
| TXT/EPUB/CHM/PDF 与至少一种其他格式跨设备恢复 | 在各格式支持范围内恢复；内容变化时正确降级，不用 0% 覆盖已保存位置 |
| 两设备并发、请求乱序、离线重连 | 修订冲突明确；旧请求不覆盖新位置；回读较早章节可被正确保存 |
| 目录内换书、列表重新排序、扫描截断 | 以文档身份恢复最后一本，缺失不静默换书 |
| 清空/关闭记录，旧标签页仍上传进度或迟到的打开回执 | 不复活记录；重新启用需新的显式搜索或打开操作 |
| 关闭搜索历史，或关闭最近阅读但保留进度同步 | 前者不落待完成查询和快照；后者仍能独立创建、恢复和同步进度 |
| A 退出后 B 登录，A 的后台标签页恢复 | 正文和个人状态清理；A 的待同步数据不能写入 B |
| 旧 Cookie/localStorage 选择性导入 | 不自动认领、不伪造时间、无权限路径被拒绝，不默认覆盖服务端进度 |
| Waitress 8 线程 + 同机多个 WSGI worker | 不跨线程复用连接；会话和密钥一致；写锁重试有界 |
| 数据库锁、磁盘满、迁移失败 | 认证失败时拒绝访问；历史保存失败可见；不返回假成功 |
| 删除/降级最后管理员、并发管理员操作 | 事务内保持至少一个可用管理员，恢复入口可用 |
| 备份恢复和版本回滚 | 数据完整，旧会话撤销，回滚不开放匿名访问 |
| WSGI 子路径、HTTPS 反代、OpenSearch 和旧书签 | URL/Cookie 前缀正确，登录后回跳安全，兼容行为有明确说明 |

实现时对身份隔离、事件幂等、文档身份、同步冲突和恢复流程编写有实际行为意义的自动化测试；阅读格式和正文隔离补充浏览器验证。并发性能以目标设备实测为准，不按账号总数直接承诺容量；若持续出现写锁等待或需要多机写入，再评估迁移服务端数据库。

## 12. 实施前可调整的产品选择

共享文档库的方向已经确认，其他未确认项按本文建议推进设计，不将其描述为已经实现或已获用户确认：

- 管理员创建账号、无公开注册，管理员重置密码。
- 首期历史包含搜索与阅读，阅读进度单独管理。
- 历史期限、数量上限和会话期限使用本文默认值。
- GET 旧书签/OpenSearch 只读兼容，不自动新增搜索事件。
- 清空最近阅读保留进度，清空全部阅读数据同时删除进度。
- 文件移动自动跟踪、精细文档授权和其他登录方式留待后续需求。

## 13. 实施记录与追加书架

用户后续要求“按文档内容进行落地”，并追加“书架”和进度记录。实现保留 Bottle 和 Recoll，以 SQLite schema v1 管理应用数据。

| 责任 | 实施位置 |
| --- | --- |
| SQLite、密码、账号、会话、事务、历史、代际、书架、备份恢复 | `accounts.py` |
| 显式初始化、账号恢复、定时清理、备份恢复入口 | `manage.py` |
| 统一认证/CSRF、账号/管理员页面、历史与书架列表 | `account_web.py`、`views/account_*.tpl` |
| 搜索事件编排、文档身份、书架/阅读回执/进度 API | `webui_data.py`、`webui.py` |
| 阅读位置恢复、节流、CAS 冲突、跨标签页退出 | `static/reader/account-sync.js`、`static/reader/app.js`、`static/accounts.js` |
| 本地 PDF.js 画布阅读及页号/页内位置 | `static/reader/pdf-adapter.js`、`vendor-build/pdfjs/` |
| 初始化、定时清理、HTTPS/WSGI、故障恢复说明 | `docs/accounts-and-history.md`、`README*.rst`、`examples/` |

书架不由“最近阅读”自动生成，必须主动加入；书架引用共享文档身份，但条目和进度只属于当前账号。加入不伪造阅读回执，移出不删除位置；清空最近阅读或全部阅读数据保留书架，显式清除进度会删除书架书籍的位置。书架条目及关联进度免于自动过期/数量淘汰。

实施选择：未知 WAL 修复状态的 SQLite 版本使用 DELETE 日志模式；已知修复版本使用 WAL。待同步进度仅保存在当前页面内存中，关闭页面后不保证未提交位置保留。PDF 使用本地固定版本 PDF.js 核心画布接口，支持翻页/页内位置，不提供文本选择、交互表单或文档脚本执行。文件移动不自动跟踪，容器内文档直接继续阅读受支持边界限制。

自动化覆盖账号事务与并发、WSGI 认证、真实 Recoll 查询/下载/书架/进度、前端冲突与重试；浏览器验证覆盖桌面和触屏阅读。完整测试命令和运行边界见操作说明。
